# 可核验交付与恢复

## 证据分层

| 证据 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| JSON Schema、单元测试、模拟对端 | 参数边界与程序行为 | 当前机器已连接Photoshop |
| PSD文件头 | 文件类型、尺寸、色彩模式字段 | 图层可编辑、软件可正常打开 |
| Photoshop成功回执+真实文件 | 指定操作有明确返回 | 全部价格、场次和视觉都正确 |
| 保存后实际重开、读取图层 | 此交付可被该PS读取，文字/结构可核对 | 审美一定符合用户预期 |
| 原尺寸预览+来源对照 | 可检查商品、排版、边缘及文案 | 自动视觉判断绝对可靠 |

未实际执行的检查写 `not_verified`。回执中要保留检查范围scope，不能只读更新组却宣称审核全部隐藏备份。

## 每批输出检查

- 对照最新版需求变更表与交付矩阵，确保删除的规则未补回，每个有效场次/尺寸都有文件。
- 价格按场景核对ID/颜色及来源，立省运算正确；标题时间和规则正文同步，全天不含4小时误导文案。
- 回读真实文本、字体、可见性、bounds、字号、删除线；对文字换行做有限规范化，保留实际语义与标点。
- 查看实际预览：商品不变形不缺角，图与价格顺序正确，无文字遮鞋、错误抠图、明显接缝、重叠或越界。联系页看全套，局部看边缘和小字。
- 透明图检查Alpha，PSD保留原生编辑层及内嵌素材。PNG/JPG按用途导出，CMYK母版需在临时RGB副本导图，不能为导出改变原母版色彩空间。
- 保存后重新打开PSD，记录当次文档ID、尺寸及图层证据。关闭自己创建的验证文档，不关闭用户原先文档。
- 核对源文件前后SHA-256；PNG切片逐像素一致、JPG尺寸正确；预览用相对链接，ZIP检查CRC及条目数量。

按阶段保存 `requirements.json`、`asset-bindings.json`、`plan.json`、执行日志、`receipt.json`、真实预览、重开核验、输入散列和交付清单。它们是推荐记录名，不要求所有项目重复造相同结构。

## 超时与失败

1. 送出之前的校验失败：修正参数/素材后可重新提交，前提是没有实际操作。
2. PS明确返回失败：检查回执中的阶段、文档ID、部分输出及当前文档。修改可能已部分生效；不要覆盖原输出。确定状态后用新的干净副本重新规划。
3. 指令已送出却超时/断连/回执丢失：结果为不确定。保留attempt、命令、结果文件和日志，阻止后续修改。先查原命令是否仍在执行、进度文件及PS当前状态；只读调用本身也可能在忙碌PS后排队，不要持续并发探测。
4. 不以重放命令或增加无限重试来“恢复”。不能因Esc无反应就擅自强制结束PS。确需重启、可能丢未保存文档时，先确认本次用户许可与文档情况；历史的一次许可不自动延续。
5. 恢复时确认原请求已终止、准确的工作文档/副本及散列、部分文件和当前会话，再从新运行目录执行。保留原失败证据，不把新成功改写成旧命令成功。

## 向用户报告

先给实际结果与预览/文件链接，然后说明检查范围及材料性限制，例如缺素材、价格模板待填、仅离线验证或UXP未验证。结构检查通过和用户审美认可分别记录；无需为普通本地修改增加无关审批流程。
